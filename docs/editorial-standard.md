# Editorial Standard

## Normal issue composition
- A normal issue is three or four A4 pages. Three pages are preferred only when the material fits without visible compression.
- Page 1: one Deep Dive, about 800-1050 words.
- Page 2: Site Problem and Detail/Product case, about 450-650 words each.
- Three-page issue: Page 3 contains two Engineering Wins, about 300-475 words each, plus Thread, 60-Second Takeaway and archive recall.
- Four-page issue: distribute the two Engineering Wins and the closing synthesis across Pages 3 and 4 according to complexity. Keep cases together where practical and avoid a mostly empty overflow page.
- Total target: 2300-2900 words. This is a useful editorial range, not a quota.

## Readability before page count
- Preserve the established magazine rhythm before preserving a three-page count.
- Edit repetition and low-value prose first when a page is crowded.
- If useful verified content still requires tighter-than-normal typography, leading, source treatment, diagram scale or module spacing to fit in three pages, use four pages and record the reason in `issue.yml`.
- Do not treat minimum typography values as targets. A page that technically clears the minimum but looks materially denser than the established Casebook style has failed editorial review.

## Required editorial behaviours
- Prefer reinforced concrete, foundations, retaining structures, slopes, groundwater, drainage, earthworks, temporary works, construction sequencing and building structures, while maintaining disciplinary variety.
- At least one case per issue should resemble ordinary building/site practice.
- Do not select a case solely because it is spectacular.
- Deep Dives reconstruct mechanics, chronology, decisions and evidence rather than merely summarising the event.
- Use `YOU ARE THE ENGINEER` decision points when they genuinely exercise judgement.
- Include meaningful calculations only when published data support them.
- Clearly separate DOCUMENTED FACT, INVESTIGATOR/AUTHOR FINDING and ENGINEERING INTERPRETATION where ambiguity matters.
- Every case ends with a visible `Sources for this case` dossier.
- Every issue ends with `The Thread`, `60-Second Takeaway`, and one archive recall question.

## Evidence gaps
Say what is not known. Never fill gaps with plausible dimensions, products, reinforcement, soil parameters, code breaches or motives.
