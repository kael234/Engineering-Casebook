# Engineering Casebook Magazine Style

## Format
- A4 portrait.
- Three pages normally; four only with a recorded content-driven override.
- Page 1: full-page Deep Dive.
- Page 2: Site Problem + Detail/Product case.
- Page 3: two Engineering Wins + Thread + 60-Second Takeaway + archive recall.

## Visual character
Technical magazine, not corporate report. Restrained warm-white page, dark navy/charcoal text, one warm accent colour, generous but efficient spacing, strong serif/sans hierarchy, no decorative gradients or stock-report chrome.

## Typography
- Body >= 8.5 pt.
- Secondary >= 8 pt.
- Sources/captions >= 7 pt.
- Deep-dive title large enough to establish clear hierarchy without consuming technical space.
- Source dossiers are visually legible, not footnotes sacrificed to pagination.

## Page 1 — Deep Dive
Use an asymmetric two-column grid rather than automatic newspaper balancing. Include:
- concise context/metadata strip;
- `YOU ARE THE ENGINEER` decision box where useful;
- chronology or evidence sequence;
- at least one genuine free-body/load-path/engineering-section figure;
- second technical figure for mechanism, failure sequence or intervention;
- meaningful numeric reconstruction where source data permit;
- Engineer's Notebook;
- clearly ranked source dossier.

## Page 2 — Problems from Practice
Do not force equal 50/50 heights. Allocate space to complexity, typically 55/45 or 50/50. Each case should use the visual form that best teaches it: section, detail, timeline, comparison table, process chain or monitoring plot.

## Page 3 — Engineering Done Well
Two materially different wins. Prefer one structural/civil and one geotechnical/site case. Show what constraint made the solution clever, what alternatives existed, what system/product was actually used, and measured outcome where available.

The closing synthesis band is a real conclusion, not microprint. Give Thread, takeaways and recall enough height to read comfortably.

## Figure vocabulary
Select from:
- context/elevation;
- free-body/load path;
- section/cutaway;
- failure sequence;
- before/after intervention;
- product detail;
- monitoring plot;
- options comparison.

Avoid repeating the same visual composition for every case.

## Source treatment
Every case ends with `Sources for this case`.
- Primary source first and visibly identified.
- Supporting technical sources after it.
- Include organisation, full report/paper title, date/year where available and live hyperlink.
- Prefer 1–3 strong sources over a bibliography-shaped hedge.

## Density
Target 2300–2900 words total. Use available page area efficiently. Do not solve overflow by shrinking below typography limits; do not leave large unexplained dead zones while omitting useful engineering content.

## PDF quality gate
Render pages to images and inspect visually before publication. Reject clipping, overlaps, unreadable labels, weak hierarchy, excessive dead space, repetitive figure treatment, tiny sources or diagrams that communicate only the headline rather than the mechanics.
